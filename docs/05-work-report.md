## 2. 단계별 작업 내역

### 1단계 — 기반 구축
- 프로젝트 기본 틀: 접이식 사이드바, 현재 위치 표시, ⌘K 메뉴 검색, 테마 전환
- Vercel 배포 설정(SPA 라우팅), 환경변수 예시, GitHub 연결

### 2단계 — 설계 문서, DB, 로그인, 기준정보
- **설계 문서 4종:** 업무 흐름도, 전표 흐름·정합성 규칙, ERD·테이블 정의, 기준정보 정의
- **DB:** 기준정보와 입고 전표(입고예정 IP → ASN AS → 상차 LD → 검수 GR) 전체 스키마
  - 감사 컬럼 자동 기록, 테이블별 이력(`_hist`), 전표번호 자동 채번
  - 상태 변경은 업무 함수(RPC)로만 가능, 전표 추적 뷰
- **로그인·권한:** 이메일 로그인, 역할별 메뉴 노출, 화주별 데이터 격리(RLS)
- **기준정보 화면 7종:** 회사, 화주사, 센터, 품목(엑셀 일괄등록·목록 다운로드), 차량, 공통코드(2단계), 사용자
- **사용자 관리 서버 함수:** 계정 생성, 수정, 비밀번호 초기화, 미사용 처리 시 로그인 차단
- **사용 중 개선:** 품목 엑셀 제목 행 누락 수정, 양식에 작성안내·참고코드 시트 추가, 업로드 진행 상태·오류 사유 표시

### 3단계 — 입고예정 등록·승인
- **입고예정:** 직접 입력(품목 검색)·엑셀로 등록. 승인대기 상태에서만 수정·취소 가능
- **승인:** 전표 단위 최종 승인 + 품목 라인별 검토
  - 승인수량은 0 ~ 예정수량, 줄이면 사유 필수
  - 반려할 때는 사유를 입력하고, 그 사유가 화주에게 표시됨
- **품목 승인:** 화주가 등록하면 3PL이 승인·반려
  - 승인 후 화주가 수정하면 다시 승인을 받아야 함
  - 승인된 품목만 입고예정에 사용 가능
- **차량:** 화주가 직접 등록. 다른 화주가 같은 차량번호를 등록해도 허용하고, 관리자는 그 차량을 쓰는 화주 목록을 확인
- **대시보드:** 3PL용과 화주사용을 분리. 화주사용은 조치 필요, 최근 입고예정, 바로가기 중심
- **복사 등록:** 반려·취소된 입고예정을 복사해 다시 등록

### 4단계 — ASN·상차지시서·PDA 상차
- **ASN:** 화주사가 같은 날짜의 승인분을 차량별로 배정
  - 여러 입고예정의 품목을 한 차량에 실을 수 있고, 상차 시작 전까지 수정·취소 가능
  - 3PL은 조회만 가능
- **상차지시서:** A4 1장, ASN 번호 Code128 바코드, 품목별 지시수량
- **PDA 상차(`/pda`)**
  - 상차지시서 스캔 → 품목 스캔 → 수량 누적
  - 바코드가 없으면 목록에서 선택, 잘못 넣은 수량은 정정
  - 지시수량과 모두 같아야 상차완료
  - 스캔·수동 입력·정정 1건마다 이력을 남김
- **화주 대시보드:** 승인됐지만 차량에 배정하지 않은 품목을 할 일로 표시

## 3. 주요 의사결정

| 구분 | 결정 |
|---|---|
| 사용자 | 3PL 내부(관리자·운영자·작업자) + 화주사 사용자, 로그인 계정 = 사용자 |
| 기준정보 | 7종(요청 6종 + ASN용 차량). 센터는 기본 1개. 품목은 3PL 내부코드(자동채번)와 화주 코드를 분리 |
| 입고 승인 | 3PL 관리자·운영자가 전표 단위로 최종 승인, 라인별로 감량 가능(사유 필수) |
| 품목 등록 | 화주사 직접 등록 + 3PL 승인, 수정 시 재승인 |
| 차량 | 화주별 등록, 화주 간 같은 차량번호 허용. ASN은 화주별, 검수는 차량번호로 묶어 조회 |
| ASN | 화주사가 등록하고 3PL은 조회. 같은 날짜 승인분만 배정 |
| PDA | 같은 웹앱의 전용 화면, 스캐너는 키보드 입력 방식. 상차 수량은 스캔마다 누적 |
| 이력 | 모든 테이블에 `_hist` 이력 테이블. 컬럼을 바꿀 때는 기존 이력을 보존한 채 재구성 |
| AI 판독 | 입고예정 이미지(카톡·메일) AI 판독은 별도 단계로 분리(Claude API 키·비용 결정 필요) |

## 4. 정합성 규칙 구현 현황

| 규칙 | 내용 | 상태 |
|---|---|---|
| R1·R2·R2-1 | 승인대기에서만 수정, 승인된 품목만, 승인수량 범위·감량 사유 | ✅ |
| R3·R3-1·R4·R5 | 승인분만 같은 날짜로 배정, 배정 합계 ≤ 승인수량, 화주·차량 일치 | ✅ |
| R6·R7 | 지시 품목만 상차, 상차수량 = 지시수량일 때 완료 | ✅ |
| R8~R11 | 검수 시작 조건, 로트·유통기한, 반송 사유·사진, 수량 차이 기록 | 일부(R9) ✅, 나머지 5단계 |
| R12·R13 | 상태는 업무 함수로만 변경, 진행된 전표 삭제 금지 | ✅ |

## 5. 진행 중 이슈와 조치

| 이슈 | 조치 |
|---|---|
| 품목 목록 다운로드 시 데이터가 0건이면 열 제목도 빠짐 | 제목 행을 항상 출력하도록 수정 |
| 일괄등록 업로드 후 아무 반응이 없어 상태를 알 수 없음 | 업로드 영역 재구성: 진행 상태, 파일명, 오류 사유, 건수 표시 |
| 3단계 DB 적용 중 기존 이력을 옮기다 실패 | 원인(이력 테이블 필수값 제약)을 수정한 뒤 재적용. 실패한 시도는 롤백되어 데이터 영향 없음. 재현 테스트 추가 |
